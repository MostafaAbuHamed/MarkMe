# Contract: `@markme/database` and Database Commands

What apps and contributors get from `packages/database` after M1 (FR-029–FR-032; research R10,
R11).

## Package exports (`packages/database/src/index.ts`)

| Export                                                                                 | Source                 |
| -------------------------------------------------------------------------------------- | ---------------------- |
| `Database`, `Json`                                                                     | generated (unchanged)  |
| `Tables`, `TablesInsert`, `TablesUpdate`, `Enums`, `Constants`                         | generated, re-exported |
| `SearchItemRow` = `Database['public']['Functions']['search_items']['Returns'][number]` | hand-written alias     |

Types only, apart from the generated `Constants` (enum value lists). No Supabase client, no runtime
code: the client factory belongs to `packages/domain` (M2, constitution II).

`src/types.gen.ts` is generated by `pnpm db:types` and committed. CI's `db` job regenerates it and
fails on any difference (M0, unchanged).

## Files

```text
packages/database/supabase/
├── migrations/
│   ├── <ts>_extensions_and_types.sql   # private schema, enums, set_updated_at
│   ├── <ts>_profiles.sql               # table, grants, RLS, handle_new_user + trigger
│   ├── <ts>_folders_tags.sql           # tables, indexes, grants, RLS
│   ├── <ts>_items.sql                  # items, item_tags, FK, indexes, grants, RLS, updated_at
│   └── <ts>_search.sql                 # vector builder, triggers, search_items
└── tests/
    ├── helpers/identity.psql           # \ir-included, pg_temp only
    ├── 000-smoke.test.sql              # existing
    ├── 010-schema.test.sql
    ├── 020-profiles.test.sql
    ├── 030-folders.test.sql
    ├── 040-tags.test.sql
    ├── 050-items.test.sql
    ├── 060-item-tags.test.sql
    └── 070-search.test.sql
```

Migrations are created with `pnpm db:new <name>` so timestamps are real; the names above are the
`<name>` part. Each table's migration carries its own grants and RLS policies, so no table exists
without them at any commit (constitution I).

## Root commands

| Command         | Status   | Does                                                                       |
| --------------- | -------- | -------------------------------------------------------------------------- |
| `pnpm db:reset` | existing | rebuild local DB from migrations + `seed.sql`                              |
| `pnpm db:test`  | existing | run all pgTAP files                                                        |
| `pnpm db:types` | existing | regenerate `types.gen.ts` from the local DB                                |
| `pnpm db:new`   | existing | new timestamped migration                                                  |
| `pnpm db:push`  | **new**  | `supabase db push --workdir packages/database` to the linked cloud project |

`db:push` needs a prior `pnpm exec supabase login` and `supabase link --project-ref <ref> --workdir
packages/database` (the ref stays in git-ignored `supabase/.temp/`). It prompts for the DB password
unless `SUPABASE_DB_PASSWORD` is set in the shell. Never in CI (A11).
